# 双 RTX 3090：短跑探索进度

> 更新时间：2026-10-03 12:31 CST。以下是服务器实测快照，不是预期进度。
> 本队列仅负责双 3090；L20 已交由另一位负责人，不在本队列操作范围内。

## 为什么要做

历史 14B 微调已证明任务可学，但扩大 LoRA rank 收益较小，已有命名/证据选择偏差。新机器实际为两张 24GB RTX 3090，而非第二张 L20，两卡跨 NUMA 连接、无 NVLink。

原计划两张卡并行做完整 QLoRA 重训，实测约 80–85 秒/优化步，300 步需要约 7 小时训练，还未计入评测。因此改为固定预算短跑，先筛选方法再考虑完整复验。量化主要为适配显存，不代表推理或训练必然更快。

当前分工：**GPU 0 顺序短跑训练，GPU 1 按顺序预测与评分**，使新方案训练与上一方案评测重叠。

## 假设与实验设计

- 对照：原输出顺序 `issue_name → stance → argument_chain`。
- 变体：每张卡的输出字段顺序改成 `argument_chain → issue_name → stance`，其余标签内容保持不变。
- 假设：先生成证据可能减少贴原文命名或证据与议题不一致；本次仅检验字段顺序，**不是完整的证据提取/归组/生成多阶段模型**。
- 每个学习率各有基线和证据先行，比较时不得跨学习率直接归因。
- 每组独立从基座训练；停止的旧长训日志与产物保留，不混入短跑。

## 遇到的问题与修正

1. 系统缺 ensurepip：以用户级 virtualenv 建独立环境，不修改系统 Python。
2. 短样本2步冒烟通过，但旧完整训练遇长样本OOM：暂停自己的队列并保留日志，加入 Liger 融合线性CE。
3. 修复后最长16条训练样本（最长约5600 token）、累积16微批、一次完整优化步验证通过，再启动训练。
4. GPU 1 单样本生成是当前瓶颈：S01预测约2小时23分、S02约2小时03分，远超过训练约54分钟。因此原5–6小时总预算偏乐观，评测积压会延长总时长。
5. 接续队列原等全部评测完成，造成GPU0空闲：已改为初始四组训练结束即训练S05/S06，GPU1仍等待初始评测释放，防止抢卡。

## 自动化与边界

- `scripts/sprint_3090.py`：四组固定预算训练/评测流水线，记录每个阶段状态与命令。
- `scripts/sprint_followup.py`：两组预声明接续实验，CPU/训练和评测分工同上。
- `scripts/monitor_3090.py`：读取训练/实际生成步数、失败和评分；当前每分钟检查，cron每10分钟尝试拉起，文件锁防重复。
- 已退出的队列有限恢复（最多3次），不会杀掉仅日志静默的训练，不会偷偷修改超参数。
- 远端是规则监控，不是持续调用AI；未知异常需进一步诊断。网站同步器依赖本地后台，过期不能当作正常状态。
- 原始结果、金标和私人连接信息不进入公开仓库；公开数据仅为实验汇总。
