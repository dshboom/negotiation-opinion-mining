## 1. 任务与评分口径（回放）

- 任务：给定中文时政/外交长文本，输出「议题 + 立场 + 原文证据」三元组，并预测未来表态。
- 综合分 = **0.8 × 观点抽取 + 0.2 × 未来观点预测**。
- 抽取判定：立场必须**严格相等**（硬门槛）→ 议题名/证据链用 `bge-small-zh` 算余弦，`0.4×议题 + 0.6×证据 > 0.7` 记为正确 → 二部图一对一匹配。
- 预测判定：ROUGE-L + BERTScore，分母取 `max(Ng,Np)`。

### 字段含义
- **NC**：正确匹配的三元组数；**Np** 预测数；**Ng** 金标数。
- **P/R/F1**：`NC/Np`、`NC/Ng`、调和平均。
- **α**：成功匹配对的 BERTScore-F1 均值（语义修正系数），抽取分 = `F1 × α`。
- **rouge_l / bertscore**：未来论点的 ROUGE-L / BERTScore，分母 `max(Ng,Np)`；预测分 = 两者均值。
- **composite** = `0.8×抽取分 + 0.2×预测分`。

### 关键结论
1. **SFT 是大赢**：0.351 → 0.550(+57%)；抽取 F1 从 .489 提到 .718。
2. **r32 与 r16 基本打平**（.5527 vs .5498，差 0.003 ≈ 噪声）→ **卡点不在 LoRA 容量**，加大 rank 无意义。
3. **基座会过度输出**（Np 1719 ≫ Ng 1421）→ 拉低 P；SFT 后数量对齐良好（1411 vs 1421）。
4. **最大短板是"未来论点预测"**（ROUGE-L 仅 .21，预测分 .40）；它占 20% 权重，是当前性价比最高的提升点。
5. 与 oracle 上界(0.731)相比仍有明显空间，说明**议题名/证据质量**还有提升余地。

## 6. 无损加速（推理）—— 实测

| 项目 | HF (transformers+peft) | vLLM 0.30 | 提升 |
|---|---|---|---|
| val 300 条纯生成 | 5050s (84min) | 578s (9.6min) | **8.7×** |
| 含引擎启动(131s) | 5050s | 709s (11.8min) | 7.1× |
| 吞吐 | ~61 tok/s | 393 tok/s | 6.4× |
| **val 综合分** | **0.5527** | **0.5538** | **+0.001（无损）** |

- **任务级无损**：分数差异在噪声内；但**非逐位一致**（跨引擎数值差异，逐 token 一致率 0/8，首处分歧在第 60~624 token）。
- **训练侧**：Liger-Kernel **无增益**（50.04s→49.33s，噪声）；当前 bs=1、长序列下显存无余量加 batch，暂无可落地的无损训练加速。
- 环境：独立 `.venv-accel`（vLLM 0.30 + torch 2.13+cu130），不污染 YHLin 环境。

### 落地时的两个坑与修法
1. **`RuntimeError: Could not find nvcc`**：vLLM 默认用 FlashInfer sampler 且需 JIT。修法（官方 troubleshooting）：`export VLLM_USE_FLASHINFER_SAMPLER=0`，并用 `enforce_eager=True` 兜底。
2. **`rescore.py` 字符偏移 bug**：用 assistant 的下标去查 `full_text` 的 offset mapping，漏加 prompt 长度 → stance token 定位错位（argmax 与生成立场仅 27.8% 一致）。修复后重跑。

### 运维注意
- vLLM 的 `VLLM::EngineCore` 子进程在父进程被 kill 后**不会自动退出**，会一直占着 ~44GB 显存；需按 cmdline 匹配 `VLLM::EngineCore` 显式清理（已加入清理脚本）。

### 收益
- test 预测：85min → ~12min；calib 生成：~1.8h → ~5min。

## 7. 后处理（⑥立场校准 / ⑦k扫描 / ⑧去重）最终结果

基线 r32：综合 0.5527 / F1 0.7182。

| 方向 | 方案 | 综合分 | Δ | 结论 |
|---|---|---|---|---|
| **⑥** | **全局先验匹配**（b_neutral=0.7, b_oppose=−0.5, L1=0.0035） | **0.5678** | **+0.0151** | ✅ **最佳，已采用** |
| ⑥ | 按 doc_type 先验匹配 | 0.5661 | +0.0134 | ✅ 次优 |
| ⑥ | train-calib F1 最优（b=0.8/0.7） | 0.5638 | +0.0111 | ✅（in-sample，偏乐观） |
| ⑧ | 去重 0.85/0.90/0.93/0.96 | 0.5489 / 0.5503 / 0.5503 / 0.5523 | ≤0 | ❌ 无增益 |
| ⑦ | k=3 / 4 / 5 / 6 / 7 | 0.4387 / 0.5104 / 0.5527 / 0.5527 / 0.5527 | ≤0 | ❌ 无增益 |

**结论**
- **只有 ⑥ 立场校准有效**（+0.015，F1 0.7182→0.7366）；原理：立场是匹配硬门槛，校准减少了立场错判→更多卡片能匹配上。
- **⑦⑧ 在本题无增益**：模型本就输出 4~5 张卡、`Np(1411)≈Ng(1421)`、近似重复极少，没有可截断/可去重的空间。

## 9. Phase 1 负结果（指令探针 + SC-merge，val 全量）

| 配置 | 综合 | F1 | NC | Np | vs 0.5678 |
|---|---:|---:|---:|---:|---:|
| 基线 T=0 贪心 +⑥ | **0.5678** | 0.7366 | 1043 | 1411 | — |
| 探针 B1（概括性命名指令） | 0.5498 | 0.7134 | 1008 | 1405 | −0.018 |
| 探针 B2（一议题一卡指令） | 0.5495 | 0.7140 | 1005 | 1394 | −0.018 |
| SC-merge F=2, thr=0.80 | 0.5246 | 0.6905 | 966 | 1377 | −0.043 |
| SC-merge F=3, thr=0.80 | 0.4997 | 0.6664 | 838 | 1094 | −0.068 |
| SC-merge F=2, thr=0.65 | 0.4796 | 0.6426 | 811 | 1103 | −0.088 |
| single-best（挑最居中样本） | 0.5527 | 0.7265 | 1016 | 1376 | −0.015 |

**结论**
1. **追加指令无效（−0.018）**：模型按固定 prompt 训练，加话属分布外扰动。
2. **SC-merge 全面失败**：5 采样的众数口径比 T=0 贪心**更远离金标**（NC 1043→966）→
   **命名/选句偏差是系统性的，不是采样噪声**——模型对同一议题每次都起同类名字，只是这类名字整体偏"贴原文"，投票无法纠偏。
3. 频次过滤误伤：F=3 把卡片压到中位 4 张，真议题中"只被看到 1~2 次的微妙议题"被丢（NC 838）。
4. **T=0 贪心 + ⑥ = 推理侧最优操作点（0.5678）**；剩余提升只能来自训练侧（Phase 2）。
5. 采样成本参考：n=5×300 篇 ≈ 25 分钟（vLLM），若 32B 复现可跳过此路（已证伪）。
