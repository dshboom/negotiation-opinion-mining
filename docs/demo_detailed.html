1项目总览与环境

目标：先把「方法」在 14B 上验证透，再平移到官方指定的 32B 基座，避免在大模型上重复试错。

1.1 项目要解决什么

① 观点抽取（占 80%）

识别一篇文档里的多个议题，为每个议题给出：议题名、立场、以及支持该立场的原文证据。

② 未来表态预测（占 20%）

为每个议题预测"接下来可能的表态"，80~120 字，考察趋势判断与生成能力。

③ 合规约束

官方指定基座为 Qwen3-32B。本机先用 Qwen3-14B 完成方法验证与消融，正式提交再上 32B。

1.2 硬件与软件环境

项目配置说明 / 影响
GPU1 × NVIDIA L20（46,068 MiB，可用 ~44.4 GiB）bf16 实测约 115 TFLOPS；HAMi GPU 虚拟化
CPU / 内存2 vCPU / 24 GiB（无 swap）数据预处理是瓶颈，故把推理切到 vLLM
训练环境conda YHLin：torch 2.9.1+cu126、transformers 5.18.0、peft 0.21、accelerate 1.15、bitsandbytes 0.50.2无 nvcc → 不能源码编译 flash-attn
推理环境独立 venv .venv-accel：vLLM（含 torch）不污染训练环境；VLLM_USE_FLASHINFER_SAMPLER=0
网络HuggingFace 不可达；改用 ModelScope（模搭） + 清华 PyPI 镜像运行期零外网依赖（模型全本地）
模型Qwen3-14B（27.5 GiB）、bge-small-zh-v1.5、bert-base-chinese评分器用后两者

2赛题任务详解

理解输入输出的精确格式，是所有后续处理的基础。

2.1 输入：一篇文档

{ "sample_id": "SAMPLE_0001",
  "docs": [ { "doc_id": "DOC_0001",
              "doc_type": "国际新闻报道",       // 记者会 / 联合声明 / 评论文章 / 政策文件 …
              "publish_date": "2025-07-26",
              "full_text": "2025年7月26日，全国党史学习教育经验交流会……" } ] }

2.2 输出：结构化三段式

{ "issue_list": [
    { "issue_name": "反对脱钩断链",                     // 议题名（简短主题词）
      "stance": "support",                             // 立场：support / oppose / neutral
      "argument_chain": [ "原文原句 1", "原文原句 2" ] } // 证据链（必须逐字来自原文）
  ],                                                   // 一篇文章通常 4~5 张卡
  "future_argument": [ "与第 1 张卡一一对应的未来表态预测，80~120 字", "…" ] }

2.3 字段字典

字段含义约束 / 常见取值
issue_name议题名简短主题词；金标偏"概括性"，如「反对脱钩断链」
stance立场仅三值；oppose 在词表里是 2 个 token
argument_chain证据链（列表）必须逐字来自原文；金标 1~3 条，中位 2~3 条
future_argument未来表态预测（列表）与 issue_list 一一对应；金标逐字率 0%（纯生成）

2.4 数据划分与用途（关键纪律）

集合条数标签用途
train2400有仅用于训练
val300有所有评分与验收都在这上面；未参与训练
test300无仅用于产出提交预测，不打分
验收纪律：任何改动（后处理 / 重训）都先在 val 上验证，只有提升才允许应用到 test —— 避免在无标签的 test 上"盲试"。此外，校准集（400 条）取自 train，属模型已见数据，仅用于诊断、用于验收时会明确标注偏乐观。

3评分规则与本地评分器

test 无标签，因此我们 1:1 复刻了官方评分逻辑，作为唯一的"秤"。秤不准，后面所有结论都不成立。

3.1 观点抽取（占 80%）的完整算法

匹配流程（伪代码） 
for 每篇文档:
  sim[i][j] = 0.4·cos(议题名_i, 议题名_j)
            + 0.6·cos(证据链_i, 证据链_j)
  ok[i][j]  = (立场_i == 立场_j)          # 硬门槛
  mat = sim; mat[~ok] = -∞
  (行,列) = 匈牙利算法(-mat)               # 一对一最大权匹配
  NC = 匹配对中 sim > 0.7 的对数

P = NC / Np      R = NC / Ng
F1 = 2PR/(P+R)   α = 匹配对的 BERTScore 均值
抽取得分 = F1 × α
四个设计细节与含义
硬门槛
立场错 → 整张卡直接作废（这就是 ⑥ 立场校准的价值来源）
权重 0.4/0.6
证据链的影响比议题名更大
阈值 0.7
"像不像"的及格线；我们测得 145 张卡只差 0.05~0.10
α 系数
惩罚"证据不精准"；证据越像原文，α 越接近 1

嵌入模型：bge-small-zh-v1.5；BERTScore：bert-base-chinese（第 9 层）。

3.2 未来观点预测（占 20%）

把预测的 future_argument 与金标逐条比：预测得分 = (ROUGE-L + BERTScore) / 2，分母为 max(Ng, Np)。

3.3 综合分

综合分 = 0.8 × (F1 × α) + 0.2 × 预测得分

3.4 评分器自检：两个探针

探针 A把标准答案原样提交

预期满分，实际 1.0000 → 证明匹配与打分链路无逻辑错误。

探针 B金标议题名/立场 + 整篇原文当证据

得 0.7309（F1 0.980，但 α 仅 0.677）→ 揭示："证据"这一项几乎白送，同时 α 会惩罚"不精准的证据"。

探针 B 的启示：既然整篇原文都能过 0.7 阈值，说明"证据相似度"这一关很宽松；真要做强，应把"证据必须是原文逐字子串"变成硬约束。这一判断后来被诊断（第 9 节）修正——模型其实已经 99.2% 逐字了。

5SFT 训练方法

LoRA 微调 + 只对答案计算 loss + 官方空 think 块忽略策略。

5.1 三个核心设计

设计 1LoRA

冻结原模型，只训练注入的低秩增量矩阵，覆盖全部线性层（q,k,v,o,gate,up,down）。显存与时间成本大幅降低，且可多份适配器并存对比。

设计 2completions-only

prompt 部分 label 全部设为 −100（不参与 loss），只在"答案"上学习。让模型专注学"怎么答"，而不是复述题面。

设计 3忽略空 think 块

Qwen3 关闭思考模式时，assistant 轮仍带空的 think 前缀。复刻官方 loss_scale=ignore_empty_think，把这段一起 mask 掉，只对 JSON 算 loss。

5.2 超参数矩阵（训练）

超参数r16 运行r32 运行r32-v2 加权重训含义
LoRA rank r163232低秩维度，越大容量越强
LoRA alpha326464取 2r（官方示例惯例）
LoRA dropout0.050.050.05正则
target modulesall-linear（7 类投影层）覆盖范围
学习率1e-4，cosine，warmup 5%，weight_decay 0.01，max_grad_norm 1.0优化器设置
batchbs=1 × grad_accum=16（有效 16）显存受限所以用梯度累积
max_len6144长文档截断长度

epochs223训练轮数
保存步数每 50 步—可断点续训

6vLLM 推理加速

把"逐条 HF 生成"换成"vLLM 离线批量"，是后续一切高成本实验（5×采样等）能跑起来的前提。

6.1 为什么能快

PagedAttention

KV Cache 分页管理，显存碎片大幅减少，可同时驻留更多序列。

连续批处理

不同长度的请求动态拼批，GPU 不再空转等最长序列。

工程隔离

独立 venv，训练环境不受污染；输出格式与 HF 完全一致。

6.2 参数与实测

项目值
dtype / max_model_len / gpu_utilbf16 / 8192 / 0.95
LoRA启用（max_lora_rank=32）
关键环境变量VLLM_USE_FLASHINFER_SAMPLER=0（本机无 nvcc）
val 生成耗时84 min（HF） → 9.6 min（vLLM）
加速比8.7×（含引擎启动则约 7.1×）
分数0.5527（HF） → 0.5538（vLLM）—— 任务级无损（生成非逐位一致，约 9 条样本卡片数翻转）

6.3 踩过的坑与运维

坑 1 · FlashInfer 需要 nvcc

默认 sampler 会尝试 JIT 编译；本机无 nvcc → 必须 VLLM_USE_FLASHINFER_SAMPLER=0，必要时加 enforce_eager=True。

坑 2 · EngineCore 残留占显存

父进程被杀后 VLLM::EngineCore 子进程不退出，占约 44GB。需按 cmdline 显式清理（不能简单 pkill -f，会误杀发起清理的脚本自身）。

E1 · SFT 微调 r16 有效

综合 0.3511 → 0.5498（+0.1987）｜ 约 2 小时 ｜ 最终 loss 0.515

E4 · ⑥ 立场 logit 校准 有效 ★ 当前最佳

0.5527 → 0.5678（+0.0151）｜ NC 1017 → 1043 ｜ F1 0.7182 → 0.7366
参数
b_neutral = +0.7，b_oppose = −0.5（先验分布 L1 = 0.0035）
方法
对每张卡前向取三分类概率 → 网格搜索偏置 → 使预测立场分布最接近训练集先验分布
原理
立场是匹配的硬门槛。模型天然"中立"偏多（gold: support 862 / neutral 517 / oppose 42），往真实分布上掰，能救回一批"因立场错而整卡作废"的卡
变体
全局先验 0.5678 ＞ 按文档类型 0.5661 ＞ calib-F1 0.5638（后两者更弱；calib 集在训练中已见，偏乐观）
合规
无需标签、无泄漏；val 仅用于验收

E5 · ⑦ 卡片数 k 扫描截断 证伪

k = 3 / 4 / 5 / 6 / 7 ｜ 收益 ≤ 0
方法
用生成 log 概率给卡片排序，截断到前 k 张
结果
k=3 → 0.4387；k=4 → 0.5104；k≥5 → 0.5527（=基线）
原理

结论
无操作空间，关闭该方向

0.5489 / 0.5503 / 0.5503 / 0.5523，全部低于基线

E8 · 指令探针 B1 / B2 证伪

B1 0.5498 ｜ B2 0.5495 ｜ 均低于基线 0.5527
方法
在原 prompt 末尾追加："用简明概括的主题词命名议题"（B1）；"一个议题一张卡"（B2）
原理
SFT 模型按固定 prompt 训练；临场加话属分布外扰动，格式与口径都会漂移
收益
约 −0.018 —— 此路不通

E9 · SC-merge 自一致性合并 证伪（全场最有价值的负结果）

n=5 采样 + 共识投票 ｜ 0.4796 ~ 0.5246 ｜ single-best 0.5527
方法
T=0.7 每题独立采样 5 次 → 议题名 BGE 聚类（thr 0.65/0.80）→ 频次 ≥ F（2/3）保留 → 众数代表卡（名/立场/证据/未来）→ rescore + ⑥
结果
F2/t0.80 = 0.5246（NC 966）；F3/t0.80 = 0.4997（NC 838）；F2/t0.65 = 0.4796（NC 811）；挑最优单样本 = 0.5527
原理
模型的口径偏差是系统性的，不是采样噪声——5 次都朝同一方向偏，投票消不掉；且频次过滤会误伤"只被 1~2 次看到"的微妙真议题
成本
300 篇 × 5 采样 ≈ 25 分钟（vLLM 的红利）
结论
负收益，但直接推出"必须重训"的结论

E10 · 失败归因诊断（Phase 0） 方法论

把"分数不够高"拆成可操作的技术问题
方法
复刻评分器匹配逻辑，对 378 张未匹配金标卡逐张归因；统计证据逐字率、议题名与原文重合度、近失分布
结果
配对但相似度≤0.7：194｜立场无同调卡：101｜相似度不足：64｜配对挤占：19；近失卡 145 张只差 0.05~0.10
结果
近失对 cos(议题名)=0.52 vs cos(证据)=0.70；证据逐字率 金标 100% / 模型 99.2%
收益
决定了后续所有实验的方向（详见第 9 节）

E11 · 字段加权重训（Phase 2） 进行中

针对诊断出的短板字段提高 loss 权重
方法
自定义加权交叉熵：议题名 ×2、立场 ×3、未来论点 ×2，其余 ×1
参数
r=32, alpha=64, 3 epochs；同时跑"不加权 3 轮"对照，干净归因
原理
既然短板集中在"命名口径 / 立场 / 未来论点"，就放大这几处 loss 权重，逼模型学标准答案的表达习惯
工程
用 offset 映射把字段值定位到 token；loss 按 1024 token 分块计算，避免整段 logits 转 fp32 导致显存溢出（首版即因此崩溃）
自检
加权 token 精确落在议题名/立场上（如 中日青年友好交流 / neutral），fallback 0

E12 · 训练/推理模式对齐 基础

方法
统一 enable_thinking=False；空 think 块不参与 loss
原理
对齐官方 loss_scale=ignore_empty_think，避免算力浪费在思考标签上
收益
与其他方案行为一致，保证对比公平

11三个关键发现

① 不是"读不懂"，是"起名口径"不同

金标偏概括性主题词，模型偏爱照抄原文。意思对了，名字对不上，占判定权重 40% 的议题名项白白流失；近失卡 145 张只差 0.05~0.10。

② 证据早已"逐字抄"（99.2%）

原计划教它"照抄原文"，一查发现它早会了。真正的问题是内容里那么多句子，它选了哪一句、从哪开始截。

③ 错误是"系统性"的，不是"随机"的

同一篇答 5 遍投票，结果更差（−0.043）。因为它每次都往同一方向偏。投票救不了系统偏差，只能靠重训。

方法论价值：这三条把"分数低"从模糊感受变成了三个明确的技术靶点，并据此排除了 5 个"看起来有用、实则无效"的优化方向（⑦⑧、指令、采样投票、Liger）。

13.3 常见问题（FAQ）

Q：为什么 test 上不能反复调参？

test 无标签，改了也不知道好不好，等于盲试；且会把测试集信息"泄漏"进方案。所以一律在 val 验收。

Q：为什么多输出（基座 1719 张）会被扣分？

准确率 P = NC/Np，多吐的卡配不上对，直接拉低 P。

Q：为什么"整篇原文当证据"能拿 0.73？

因为那行探针抄了金标的议题名和立场，只剩证据一项在测；而 0.6 权重的证据项阈值很宽松（整篇原文通常也 >0.5）。

Q：为什么投票合并反而不行？

因为模型是"系统性偏差"：5 次都往同一方向偏，众数也一样偏；投票只能消除随机噪声。

Q：为什么要先用 14B？

32B 训练与推理成本高。在 14B 上把"哪些方法有效、哪些无效"摸清楚，再上 32B 只做一次高质量训练。

Q：本地评分器和官方一致吗？

按官方规则复刻，并用两个探针自检：答案照抄 = 1.0000，整篇原文 = 0.7309，逻辑自洽。
