## 0. 评测口径（所有实验共用）

```
语义等价分 = 0.4 × cos(议题名) + 0.6 × cos(证据链)      # bge-small-zh-v1.5
立场必须严格相等（硬门槛）→ 一对一匹配（匈牙利）→ 阈值 0.7 → NC
P = NC/Np    R = NC/Ng    F1 = 2PR/(P+R)
α = 匹配对的 BERTScore-F1 均值                          # bert-base-chinese
抽取分 = F1 × α                 （占 80%）
未来分 = (ROUGE-L + BERTScore)/2 （占 20%）
综合分 = 0.8 × 抽取分 + 0.2 × 未来分
```

- **评测集**：`val`（300 条，未参与训练）；`test`（300 条，无标签，仅交卷）
- **基线**：SFT r32（2 轮，HF 推理）= **0.5527**
- **验收纪律**：任何改动先在 val 验证，提升达标才应用于 test
- **评分器自检**：答案原样提交 = 1.0000；整篇原文当证据 = 0.7309

## 2. 逐实验详情

### E1 · SFT LoRA r16 ✅
- **参数**：r=16, alpha=32, all-linear, dropout 0.05, lr 1e-4, bs 1×ga16, max_len 6144, bf16, warmup 5%, 2 epochs
- **方法**：`train_lora.py`；completions-only；空 think 块 mask（复刻官方 `ignore_empty_think`）
- **训练**：最终 loss 0.515，约 2 小时
- **结果**：0.3511 → **0.5498**（+0.1987）；F1 0.489→0.713
- **结论**：微调是最大的单项提升，任务可学。

### E2 · SFT LoRA r32 ✅（微增）
- **参数**：r=32, alpha=64，其余同 E1
- **结果**：0.5498 → **0.5527**（+0.0029）；loss 0.504
- **结论**：**容量不是瓶颈**；后续不再尝试 r64。

### E3 · vLLM 推理加速 ✅（工程）
- **参数**：bf16, max_model_len 8192, gpu_util 0.95, LoRA 启用, `VLLM_USE_FLASHINFER_SAMPLER=0`
- **结果**：val 生成 84 min → **9.6 min（8.7×）**；综合 0.5527 → **0.5538**（**任务级无损**）
- **结论**：让"5×采样"等重实验变得可行（300 篇 × 5 ≈ 25 min）。

### E4 · ⑥ 立场 logit 校准 ✅ ★
- **参数**：b_neutral = +0.7, b_oppose = −0.5（先验分布 L1 = 0.0035）
- **方法**：`rescore.py` 取三分类概率 → `fit_bias.py` 无标签先验匹配 → `apply_stance_calib.py`
- **原理**：立场是匹配**硬门槛**，立场错则整卡作废；模型"中立"偏多
- **结果**：0.5527 → **0.5678**（+0.0151）；NC 1017 → 1043
- **变体对照**：全局先验 0.5678 > 按文档类型 0.5661 > calib-F1 0.5638（后者为训练内数据，偏乐观）

### E5 · ⑦ 卡片数 k 扫描 ❌
- **方法**：按生成 logp 排序，截断到 k=3/4/5/6/7
- **结果**：k≥5 = 基线（0.5527）；k=3 → 0.4387，k=4 → 0.5104
- **原因**：Np ≈ Ng（1411 vs 1421），**无多余卡片**

### E6 · ⑧ 近重复去重 ❌
- **方法**：议题名 BGE 余弦 > 0.85/0.90/0.93/0.96 判重
- **结果**：0.5489 / 0.5503 / 0.5503 / 0.5523，**全部低于基线**
- **原因**：输出几乎无近重复

### E7 · Liger 融合核 ❌
- **结果**：单步 50.04s → 49.33s（<2%）
- **原因**：硬件瓶颈在 2 vCPU + 虚拟化 GPU

### E8 · prompt 追加指令探针 ❌
- **方法**：B1「议题名用概括性主题词」/ B2「一个议题一张卡」
- **结果**：0.5498 / 0.5495（**−0.018**）
- **原因**：分布外扰动，格式与口径漂移

### E9 · SC-merge 自一致性合并 ❌（最有价值的负结果）
- **方法**：`sample_vllm.py`（T=0.7, top_p=0.8, n=5）→ `sc_merge.py`（议题名 BGE 聚类，thr 0.65/0.80；频次 ≥ F；众数代表卡）→ rescore + ⑥
- **结果**：F2/t0.80 = 0.5246；F3/t0.80 = 0.4997；F2/t0.65 = 0.4796；single-best = 0.5527
- **原因**：**模型的命名偏差是系统性的**（每次都朝同一方向偏），投票只能消除随机噪声；频次过滤还误伤"只被 1~2 次看到"的微妙真议题
- **影响**：直接指向"必须重训"，并促成失败归因诊断（E10b）

### E10b · 失败归因诊断（方法论）📐
- **方法**：`diag_phase0.py`（复刻匹配逻辑逐张归因）+ `analyze_names.py`（命名口径）
- **结果**：378 张未匹配 = 配对但相似度≤0.7 **194** + 立场无同调 **101** + 相似度不足 64 + 配对挤占 19；**145 张只差 0.05~0.10**
- **结果**：证据逐字率 金标 100% / 模型 **99.18%**；议题名原文子串率 金标 13.7% / 模型 **23.7%**
- **结论**：短板在**命名口径**与**选句**，不是"读不懂"

### E11 · 字段加权重训 🔄（进行中）
- **方法**：`train_lora_v2.py`；对 `issue_name` ×2、`stance` ×3、`future_argument` ×2 的 token 加权
- **工程**：字符区间定位字段 → offset 映射到 token → 加权交叉熵（**按 1024 token 分块**，避免 fp32 logits OOM）
- **对照**：同条件不加权 3 轮
- **状态**：待结果

### E12 · 训练/推理模式对齐 📐
- **方法**：统一 `enable_thinking=False`；空 think 块不参与 loss
- **结论**：保证与官方最佳实践一致

### E13 · Qwen3-32B ✅（总最佳）
- **结果**：F1 0.773 / α 0.849 / 抽取 0.665 / 未来 0.380 / **综合 0.6082**
- **观察**：抽取显著变强（+0.057），**但未来论点反而退步（0.408 → 0.380）**
- **结论**：基座升级可解决"命名口径/选句"部分，但**未来论点需要从数据与训练方法入手**

## 4. 关键结论速记

1. **微调 >> 后处理**：0.3511 → 0.5527 来自微调；后处理里只有 ⑥ 有效（+0.0151）。
2. **瓶颈是"口径"不是"理解"**：模型找对议题、证据逐字率 99.2%，但命名与金标风格相反。
3. **系统性偏差无法投票**：需要重训，或换更强基座（32B 已验证抽取变强）。
4. **未来论点是当前最大单点短板**（32B 上仅 0.380，占 20% 权重）。
